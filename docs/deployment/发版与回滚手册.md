**两条必须理解的前提：**

1. **部署目录没有 git 元数据**（当初是手动上传的），所以服务器上不能 `git pull`，

2. **目录名 `anttransfer` 必须保持不变**。Compose 默认用所在目录名作为 project 名，
   它决定了数据卷的前缀 `anttransfer_*`。一旦把目录改成别的名字再 `up`，
   Compose 会认成另一个项目、去挂一组**全新的空卷**——表现为「所有用户和文件凭空消失」。

## 二、发版前：本机打包

工作目录：`e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community`

```powershell
cd "e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community"
git fetch origin
git status -sb          # 必须是干净的工作区，且已位于要发布的提交上
git log --oneline -1    # 记下这行 commit id，回滚和排查时要用

# 记下要烙进镜像的版本元数据——必须在这里取，不能等到服务器上再问 git：
# 服务器拿到的是 git archive 展开的源码，没有 .git/（.dockerignore 也排除了它），
# 到那边再想 rev-parse 已经问不出来了，镜像标签只会得到 unknown。
git rev-parse HEAD                  # → GIT_COMMIT（下面 3.1 的 4.5 步要用）
git rev-parse --abbrev-ref HEAD     # → GIT_BRANCH

# 打包：只含已提交内容，天然排除 .env / target/ / node_modules / web/dist
git archive --format=tar.gz -o "$env:TEMP\anttransfer-src.tar.gz" HEAD

scp "$env:TEMP\anttransfer-src.tar.gz" root@101.43.55.53:/tmp/
```

为什么用 `git archive` 而不是直接压缩整个目录：它按 Git 索引出包，`.gitignore` 里
那些本地配置、密钥、构建产物一个都不会带上，体积小且不会误传 `.env`。

> **粘错目录时的报错对照**（真实踩过）：
>
> - `fatal: 'origin' does not appear to be a git repository` —— 命令不是在项目仓库里执行的。
>   典型情形是在 `C:\Users\<用户>` 家目录下执行：那里被别人 `git init` 过，会显示
>   `No commits yet on master`，并把 `NTUSER.DAT`、`.ssh/` 一堆家目录文件列成未跟踪文件。
>   先 `cd` 到项目目录，或用 `-C` 指定仓库（任意位置都能跑）：
>   `git -C "e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community" status -sb`
> - `warning: could not open directory 'Application Data/': Permission denied` 这类成片告警，
>   是 Windows 家目录的权限噪音，与部署无关，切到项目目录后自然消失。
>
> `git archive` 的 `-o` 用的是 `$env:TEMP\...` 绝对路径，所以产物落在哪里与当前目录无关。

## 三、后端发版

### 3.1 服务器执行

⚠️ **先读这一段，三步红线**（都是生产上真实踩过的）：

1. **不要把整段命令逐条粘进交互式 shell，更不要在那里执行 `set -e`。**
   交互式 shell 下 `set -e` 会让**任何一个非零返回**（包括粘贴时被打散的语法错误）
   直接把 shell 干掉，终端显示 `Connection closed`，宝塔面板则是「连接已断开」。
   现象看起来像服务器崩了，其实只是会话退出，磁盘和容器都没事。
2. **不要用 `\` 续行写多行命令再粘贴。** 终端拆行后会把 `&&` 变成独立命令，
   报 `bash: syntax error near unexpected token '&&'`。
3. **`docker compose` 必须在 `/home/ubuntu/anttransfer` 目录内执行。**
   在家目录跑会报 `no configuration file provided: not found`——Compose 只认当前
   目录或 `-f` 指定的文件。

正确做法：**先写成脚本文件，再交给 `bash` 执行**。

```bash
cat > /tmp/deploy-server.sh <<'SCRIPT'
set -euo pipefail
cd /home/ubuntu

# 1) 解包到新目录（先不碰正在运行的目录）
rm -rf anttransfer.new && mkdir anttransfer.new
tar -xzf /tmp/anttransfer-src.tar.gz -C anttransfer.new

# 2) 关键：把 .env 带过去。这是唯一一份，丢了下一步会直接拒绝启动
cp anttransfer/.env anttransfer.new/.env

# 3) 旧目录带时间戳留底
#    不要固定写 anttransfer.bak：该目录已存在时再 mv，会把整棵新目录
#    塞进备份目录内部（变成 anttransfer.bak/anttransfer），替换就错位了
if [ -d anttransfer ]; then
  mv anttransfer "anttransfer.bak.$(date +%F-%H%M)"
fi
mv anttransfer.new anttransfer

# 4) 可选：依赖包拷回（见 3.2），文件不存在时自动跳过
if [ -f /home/ubuntu/m2-repository.tar.gz ]; then
  mkdir -p anttransfer/deploy/docker/m2
  cp /home/ubuntu/m2-repository.tar.gz anttransfer/deploy/docker/m2/
fi

cd anttransfer

# 4.5) 版本元数据写进 .env，供下一步构建注入镜像标签与应用内 build-info。
#      为什么写 .env 而不是 export：Compose 会自动读取同目录 .env 做变量插值，
#      所以不依赖当前 shell 环境、也不依赖「谁记得先敲 export」——
#      换人执行、SSH 重连、脚本方式运行，结果都一致。
#      两个值取本机第二章 git rev-parse 的输出，**必须替换为实际值**：
#      留成占位符 <...> 会让镜像标签里出现字面量 <...>，比 unknown 更容易误导人。
sed -i '/^GIT_COMMIT=/d;/^GIT_BRANCH=/d' .env
printf 'GIT_COMMIT=%s\nGIT_BRANCH=%s\n' '<本机的完整提交号>' '<本机的分支名>' >> .env

# 5) 构建前先给当前镜像打留底标签
#    build 会用 latest 覆盖旧镜像，旧镜像随即变成无标签的悬空镜像，事后难辨认
if docker image inspect anttransfer/server:latest >/dev/null 2>&1; then
  docker tag anttransfer/server:latest "anttransfer/server:prev-$(date +%F-%H%M)"
fi

# 6) 重建并替换后端容器
docker compose build server        # 单独构建，失败不影响在跑的容器
docker compose up -d --no-build server
#   --no-build：直接用刚构建好的镜像建容器，避免 Compose 再触发一次完整构建

docker compose ps
SCRIPT

bash /tmp/deploy-server.sh
```

- **不要**用 `docker compose down` 全量停服，`up -d server` 即可滚动替换，停机只有几秒。
- **绝对不要**加 `-v`（`down -v` 会删数据卷，库和已上传文件一起没）。
- **绝不要在 `anttransfer.bak*` 目录里执行任何 `docker compose` 命令**。Compose 以目录名
  作为 project 名，在备份目录里 `up` 会认成一个新项目、挂上一组**全新空卷**，表现就是
  「用户和文件凭空消失」。备份目录只作源码留底，永远只在 `/home/ubuntu/anttransfer` 里操作。
- 构建阶段在容器内跑 `mvn package`，云服务器上数分钟很正常，**不要中断**。
- 脚本可以反复执行，但**不要重复跑**：整目录替换本身是一次性动作，重复执行只会不停产生
  新的 `.bak.<时间戳>` 目录，没有任何好处。

### 3.2 构建太慢时（可选提速）

`Dockerfile` 支持依赖预热：仓库里存在 `deploy/docker/m2/m2-repository.tar.gz` 时，
镜像会先解压它再打包，省掉容器内全量下载 Maven 依赖。

```powershell
# 本机：生成依赖包（脚本在 deploy/docker/scripts/ 下）
pwsh deploy/docker/scripts/New-MavenBundle.ps1
```

```bash
# 服务器：放在部署目录之外，避免每次整目录替换被清掉
ls /home/ubuntu/m2-repository.tar.gz
```

每次整目录替换后，把依赖包拷回新目录再构建（3.1 的脚本第 4 段已包含此步，手工执行时注意**写成单行**，不要用 `\` 续行）：

```bash
mkdir -p /home/ubuntu/anttransfer/deploy/docker/m2 && cp /home/ubuntu/m2-repository.tar.gz /home/ubuntu/anttransfer/deploy/docker/m2/
```

> 依赖包**不进版本控制**，也不随源码包分发；未提供时构建自动退化为在线解析，不会失败。

### 3.3 数据库迁移

`SPRING_PROFILES_ACTIVE=prod` 下 Flyway 默认开启，`sql/` 下的迁移脚本在构建期被
打进 jar 的 `classpath:db/migration`，容器启动时**自动执行**，无需任何手工操作。

⚠️ **迁移是单向的**：Flyway 不会因为回滚镜像而撤销已执行的迁移。所以
「新版本引入了 DDL 变更」和「代码可回滚」是两件事——详见第七章。

## 四、前端发版

前端是纯静态产物，由宿主机 Nginx 托管，与后端发版**互相独立**。

```powershell
# 本机（Node 要求 >= 22，见 web/package.json 的 engines）
cd "e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community\web"
npm ci
npm run build                     # 产物在 web/dist

# 留一份本机产物，前端回滚时直接重传即可，比重新 build 快
Copy-Item -Recurse -Force dist "$env:TEMP\dist-<commit>"

scp -r dist/* root@101.43.55.53:/var/www/anttransfer/
```

若 PowerShell 对 `dist/*` 通配符处理异常（报找不到路径或把子目录漏掉），改用打包方式，更稳：

```powershell
tar -czf "$env:TEMP\dist.tar.gz" -C dist .
scp "$env:TEMP\dist.tar.gz" root@101.43.55.53:/tmp/
```

```bash
# 服务器：解包覆盖
mkdir -p /var/www/anttransfer && tar -xzf /tmp/dist.tar.gz -C /var/www/anttransfer
```

```bash
# 服务器：确认落盘（文件名带内容 hash）
ls -lt /var/www/anttransfer/ | head
```

前端无需重启任何服务。浏览器强刷（Ctrl+F5）即可看到新版本。

> **`version.json`（随 dist 一并发布）**：`npm run build` 现在会额外产出 `dist/version.json`
> （提交号 / 短提交号 / 分支 / 构建时间 / 提交时间），不必打开页面即可查现网前端版本：
>
> ```bash
> curl -sS http://101.43.55.53/version.json
> ```
>
> 配套的 `deploy/nginx/anttransfer.conf` 新增了 `location = /version.json`
> （`Cache-Control: no-store`；文件缺失时返回 **404 而不是回退到 `index.html`**）。
> **改过 nginx 模板就必须同步到服务器**并执行 `nginx -t && nginx -s reload`，
> 否则该文件可能被客户端或中间层缓存，或在缺失时静默返回一坨 HTML，让排查者误判。
> 脚本在无 git 环境（源码包 / 浅克隆）下会把 commit 记为 `unknown` 且不阻断构建。

> `scp` 只覆盖同名文件、不删除旧文件。由于 `index.html` 在 Nginx 里被配置为不缓存，
> 旧 hash 资源残留只是占磁盘，不影响功能。
>
> 同源部署下前端请求的是 `/api/**`，由 Nginx 转发到 `127.0.0.1:8080`，
> 不需要改任何接口地址。

## 六、回滚

### 6.1 首选：镜像秒回（无需重新构建）

3.1 的脚本在每次构建前都会把当时的镜像留底为 `anttransfer/server:prev-<时间戳>`。
回滚就是把该标签重新指回 `latest`，**几十秒完成，不用等 `mvn package`**：

```bash
cd /home/ubuntu/anttransfer
docker images anttransfer/server                   # 找到要退回的 prev-<时间戳>
docker tag anttransfer/server:prev-<时间戳> anttransfer/server:latest
docker compose up -d --no-build --force-recreate server
docker compose ps
```

### 6.2 备选：整目录回滚

镜像标签丢失或需要连源码一起退回时使用：

```bash
cd /home/ubuntu
ls -d anttransfer.bak.*                            # 找到上次发版留底的目录
mv anttransfer anttransfer.failed
mv anttransfer.bak.<时间戳> anttransfer
cd anttransfer
docker compose up -d --build                       # .bak 里已有 .env，无需再拷
```

> 两条路径都只回退**代码/镜像**。本次发版若带了新的 `V*.sql`，迁移不会随之撤销——见下文。

### 6.3 前端回滚

把上一版 `dist` 重新 `scp` 上去即可（见第四章的本机留底方式；本机没留就用对应提交重新 `npm run build`）。

**回滚不了的部分——数据库。** 代码可以退回旧版，但新版已执行的
`V*.sql`（建表、加列、改约束）**不会自动撤销**。因此：

- 发版前若有新的 `V*.sql`，务必先备份数据库：

  ```bash
  docker exec at-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction anttransfer' \
    | gzip > /home/ubuntu/backup-$(date +%F-%H%M).sql.gz
  ```

- 备份范围也必须覆盖文件卷，否则用户上传的内容无副本：

  ```bash
  docker run --rm -v anttransfer_files-data:/src -v /home/ubuntu:/out alpine \
    tar -czf /out/files-$(date +%F).tar.gz -C /src .
  ```

- 若新迁移包含**删列 / 改类型**这类不可逆操作，只能「回滚代码 + 从备份恢复数据库」，
  没有别的捷径。

确认新版本稳定运行几天后，再删除留底——**保留最近两份（当前版本 + 上一版本）**，只清更早的。

为什么是两份：一份刚够「退回上一版」，可一旦退回后又发现问题、还想再往回或再观察一轮，
手里就没有第二份了；两份正好覆盖「这次发版」与「上次发版」。再往前的版本早已超出
「确认稳定运行几天」这个窗口，留着只占目录。

为什么**不要留到四份**：小步多次发版时目录会迅速堆积（实测一轮维护就攒到四份，
其中三份是同一小时内的连续备份），而真正可能被用到的永远是最近那两份。
留底的价值在于**能退回、且退得回去一个明确状态**，不在于数量。

```bash
# 先看清楚：名称后缀即备份时刻（定宽，字典序 = 时间序），最新两条保留
ls -1d /home/ubuntu/anttransfer.bak.* 2>/dev/null | sort | tail -n 2    # 要保留的
ls -1d /home/ubuntu/anttransfer.bak.* 2>/dev/null | sort | head -n -2   # 待删除的（逐条核对后再执行）
rm -rf /home/ubuntu/anttransfer.bak.<明确不要的时间戳> /home/ubuntu/anttransfer.failed
```

镜像同理：`prev-*` 同样保留最近两个，逐个明确删除。**不要**用 `docker image prune -a`
（它会连留底的 `prev-*` 一起删掉，回滚手段当场失效）：

```bash
docker images anttransfer/server --format '{{.Tag}} | {{.CreatedAt}}'   # 认准时间戳再删
docker rmi anttransfer/server:prev-<明确不要的时间戳>
```

## 七、首次部署（仅在重建服务器时使用）

日常发版**不要**走这里。完整流程：

```bash
# 1) 基础依赖
apt-get update && apt-get install -y docker.io docker-compose-v2 nginx git
systemctl enable --now docker nginx

# 2) 部署目录（名字必须叫 anttransfer）
mkdir -p /home/ubuntu/anttransfer
tar -xzf /tmp/anttransfer-src.tar.gz -C /home/ubuntu/anttransfer
cd /home/ubuntu/anttransfer

# 3) 生成 .env —— 两项必填，缺失时 compose 会直接报错退出
cp .env.example .env
SECRET=$(openssl rand -base64 48)
sed -i "s|^DB_PASSWORD=.*|DB_PASSWORD=<设一个强密码>|"            .env
sed -i "s|^AUTH_ACCESS_TOKEN_SECRET=.*|AUTH_ACCESS_TOKEN_SECRET=${SECRET}|" .env
sed -i "s|^ANTTRANSFER_CORS_ALLOWED_ORIGINS=.*|ANTTRANSFER_CORS_ALLOWED_ORIGINS=http://101.43.55.53|" .env
chmod 600 .env
cat .env                            # 核对一遍
```

> ⚠️ `.env` 承载数据库密码与 JWT 签名密钥，**不在版本控制里、全服仅此一份**。
> `DB_PASSWORD` 丢了打不开已有数据，`AUTH_ACCESS_TOKEN_SECRET` 变了所有人立刻掉线。
> 生成后请立刻离线另存一份。

```bash
# 4) 起服务（首次会完整构建镜像，最慢的一次）
docker compose up -d --build
docker compose ps

# 5) Nginx 站点
cp deploy/nginx/anttransfer.conf /etc/nginx/sites-available/anttransfer
#    按服务器实际情况改 server_name 与 root（root 应为 /var/www/anttransfer）
ln -sf /etc/nginx/sites-available/anttransfer /etc/nginx/sites-enabled/anttransfer
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

前端产物按第四章上传到 `/var/www/anttransfer` 后，访问 `http://101.43.55.53/` 即可。

## 八、常见故障速查

| 现象 | 原因与处置 |
| --- | --- |
| `docker compose up` 报 `no configuration file provided: not found` | 当前目录不对（多半在家目录）。`cd /home/ubuntu/anttransfer` 后再执行 |
| 执行到一半 SSH 断开、报 `Connection closed`（宝塔面板显示「连接已断开」） | 在交互式 shell 里执行了 `set -e`：某个非零返回（常见是粘贴被打散的语法错误）直接把 shell 干掉了。**服务器与容器不受影响**，重连后按 3.1 改成脚本文件执行 |
| `bash: syntax error near unexpected token '&&'` | 用 `\` 续行的多行命令在粘贴时被终端拆散。改成单行命令，或整段写进脚本用 `bash` 执行 |
| `docker images` 里出现无标签的悬空镜像，找不到旧版本 | `build` 覆盖了 `latest`，旧镜像失去标签。`docker images -f dangling=true` 找回后 `docker tag <镜像ID> anttransfer/server:latest`；此后按 3.1 在构建前先打 `prev-<时间戳>` 标签 |
| `docker compose up` 报 `必须设置数据库密码 DB_PASSWORD` / 密钥相关错误 | 新目录里缺 `.env`。从上一份留底拷回来：`cp ../anttransfer.bak.<时间戳>/.env .` |
| 构建卡在 `transferring context` 很久 | 前端 `node_modules` 混进了构建上下文。确认 `.dockerignore` 里的 `web/node_modules/` 还在 |
| 启动日志报 `Access denied for user` | `.env` 的 `DB_PASSWORD` 与 MySQL 卷里实际密码不一致（多为换了 `.env`）。用原密码；确实丢了只能重置库内密码 |
| 重启后用户文件 / 断点续传全没了 | 卷没挂上或 project 名变了。`docker volume ls` 看是否存在 `anttransfer_files-data`；确认目录名没改 |
| 页面白屏 | 前端 `dist` 没传或空目录；也可能是 `index.html` 被缓存（Nginx 里该文件应配为不缓存） |
| 上传大文件在 Nginx 层被拒 | `client_max_body_size` 需 ≥ 100m（后端上限 80MB） |
| 实时通知一直「正在建立连接」 | Nginx 缺 `/api/ws/` 的 WebSocket Upgrade 转发块，对照 `deploy/nginx/anttransfer.conf` 补齐 |
| 接口全量 404 | `proxy_pass` 结尾多写了 `/`，前缀被剥掉。必须写 `proxy_pass http://anttransfer_backend;` |

## 九、红线

1. 🚫 任何时候都不要执行 `docker compose down -v`、`docker volume rm`。
2. 🚫 不要修改部署目录名，不要删 `.env`。
3. 🚫 不要在 `anttransfer.bak*` 备份目录里执行任何 `docker compose` 命令——Compose 按目录名
   认 project，在备份目录里 `up` 会挂到一组全新空卷。所有 compose 命令只在
   `/home/ubuntu/anttransfer` 内执行。
4. 🚫 不要把 `mysql:3307`、`redis:6379`、`server:8080` 的三个 `127.0.0.1` 绑定改回
   `0.0.0.0`——那等于把数据库和 Redis 直接挂到公网上。
5. 🚫 不要把 `.env`、私钥提交进仓库。
6. 🚫 不要在交互式 shell 里执行 `set -e`，也不要粘贴用 `\` 续行的多行命令：前者会让会话
   直接断开，后者会被终端拆行报语法错误。一律按 3.1 写成脚本文件用 `bash` 执行。
7. ✅ 发版前先 `git status` 确认干净、记下 commit id；发版后跑完第五章的验证清单。
