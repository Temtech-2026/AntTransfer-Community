>
> **读者**：负责发版的人。**前提**：生产环境已按第一章的基线存在，不需要重新初始化。

## 一、环境基线（当前生产实况）

| 项 | 值 |
| --- | --- |
| 服务器 | `root@101.43.55.53`（Ubuntu，腾讯云） |
| 部署目录 | `/home/ubuntu/anttransfer` |
| 编排文件 | `/home/ubuntu/anttransfer/docker-compose.yml`（仓库根同名文件） |
| 后端容器 | `at-server`（镜像 `anttransfer/server:latest`） |
| 依赖容器 | `at-mysql`、`at-redis`（均为官方镜像，不随发版重建） |
| 前端目录 | `/var/www/anttransfer`（宿主机 Nginx 直接读盘，**不在容器里**） |
| Nginx 站点 | 按 `deploy/nginx/anttransfer.conf` 落地，`root` 指向上面的前端目录 |
| 数据卷 | `anttransfer_mysql-data`、`anttransfer_redis-data`、`anttransfer_files-data`、`anttransfer_staging-data` |
| 对外端口 | 仅 `80`（Nginx）。`8080 / 3307 / 6379` 一律只绑 `127.0.0.1` |

**两条必须理解的前提：**

1. **部署目录没有 git 元数据**（当初是手动上传的），所以服务器上不能 `git pull`，
   发版靠**本机打包 → `scp` 上传 → 整目录替换**。
2. **目录名 `anttransfer` 必须保持不变**。Compose 默认用所在目录名作为 project 名，
   它决定了数据卷的前缀 `anttransfer_*`。一旦把目录改成别的名字再 `up`，
   Compose 会认成另一个项目、去挂一组**全新的空卷**——表现为「所有用户和文件凭空消失」。

## 二、发版前：本机打包

工作目录：`e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community`

```powershell
cd "e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community"
git fetch origin
git status -sb          # 必须是干净的工作区，且已位于要发布的提交上
git log --oneline -1    # 记下这行 commit id，回滚和排查时要用

# 打包：只含已提交内容，天然排除 .env / target/ / node_modules / web/dist
git archive --format=tar.gz -o "$env:TEMP\anttransfer-src.tar.gz" HEAD

scp "$env:TEMP\anttransfer-src.tar.gz" root@101.43.55.53:/tmp/
```

为什么用 `git archive` 而不是直接压缩整个目录：它按 Git 索引出包，`.gitignore` 里
那些本地配置、密钥、构建产物一个都不会带上，体积小且不会误传 `.env`。

## 三、后端发版

### 3.1 服务器执行

```bash
cd /home/ubuntu
set -e

# 1) 解包到新目录（先不碰正在运行的目录）
rm -rf anttransfer.new && mkdir anttransfer.new
tar -xzf /tmp/anttransfer-src.tar.gz -C anttransfer.new

# 2) 关键：把 .env 带过去。这是唯一一份，丢了下面一步会直接拒绝启动
cp anttransfer/.env anttransfer.new/.env

# 3) 目录切换（失败可原样回滚，见第六章）
mv anttransfer anttransfer.bak
mv anttransfer.new anttransfer

# 4) 重建并替换后端容器
cd anttransfer
docker compose build server        # 单独构建，失败不影响在跑的容器
docker compose up -d server        # 只替换 server，mysql / redis 不动
```

- **不要**用 `docker compose down` 全量停服，`up -d server` 即可滚动替换，停机只有几秒。
- **绝对不要**加 `-v`（`down -v` 会删数据卷，库和已上传文件一起没）。
- 构建阶段在容器内跑 `mvn package`，云服务器上数分钟很正常，**不要中断**。

### 3.2 构建太慢时（可选提速）

`Dockerfile` 支持依赖预热：仓库里存在 `deploy/docker/m2/m2-repository.tar.gz` 时，
镜像会先解压它再打包，省掉容器内全量下载 Maven 依赖。

```powershell
# 本机：生成依赖包（脚本在 deploy/docker/scripts/ 下）
pwsh deploy/docker/scripts/New-MavenBundle.ps1
```

```bash
# 服务器：放在部署目录之外，避免每次整目录替换被清掉
ls /home/ubuntu/m2-repository.tar.gz
```

每次整目录替换后，把依赖包拷回新目录再构建：

```bash
mkdir -p /home/ubuntu/anttransfer/deploy/docker/m2
cp /home/ubuntu/m2-repository.tar.gz /home/ubuntu/anttransfer/deploy/docker/m2/
```

> 依赖包**不进版本控制**，也不随源码包分发；未提供时构建自动退化为在线解析，不会失败。

### 3.3 数据库迁移

`SPRING_PROFILES_ACTIVE=prod` 下 Flyway 默认开启，`sql/` 下的迁移脚本在构建期被
打进 jar 的 `classpath:db/migration`，容器启动时**自动执行**，无需任何手工操作。

⚠️ **迁移是单向的**：Flyway 不会因为回滚镜像而撤销已执行的迁移。所以
「新版本引入了 DDL 变更」和「代码可回滚」是两件事——详见第七章。

## 四、前端发版

前端是纯静态产物，由宿主机 Nginx 托管，与后端发版**互相独立**。

```powershell
# 本机（Node 要求 >= 22，见 web/package.json 的 engines）
cd "e:\01_Coding\Projects\1-Personal\2026\0905-AntTransfer Community\web"
npm ci
npm run build                     # 产物在 web/dist

scp -r dist/* root@101.43.55.53:/var/www/anttransfer/
```

```bash
# 服务器：确认落盘（文件名带内容 hash）
ls -lt /var/www/anttransfer/ | head
```

前端无需重启任何服务。浏览器强刷（Ctrl+F5）即可看到新版本。

> `scp` 只覆盖同名文件、不删除旧文件。由于 `index.html` 在 Nginx 里被配置为不缓存，
> 旧 hash 资源残留只是占磁盘，不影响功能。
>
> 同源部署下前端请求的是 `/api/**`，由 Nginx 转发到 `127.0.0.1:8080`，
> 不需要改任何接口地址。

## 五、验证清单

后端发版后逐条过：

```bash
cd /home/ubuntu/anttransfer

# 1) 三个容器都是 Up；at-server 的启动时间应该是刚刚

#    ✅ 200
```

## 六、回滚

保留着 `.bak` 就能秒回：

```bash
cd /home/ubuntu
mv anttransfer anttransfer.failed
mv anttransfer.bak anttransfer
cd anttransfer
docker compose up -d --build          # .bak 里已有 .env，无需再拷
```

前端回滚：把上一版 `dist` 重新 `scp` 上去即可（本机若没留，从 Git 对应 tag 重新 `npm run build`）。

**回滚不了的部分——数据库。** 代码可以退回旧版，但新版已执行的
`V*.sql`（建表、加列、改约束）**不会自动撤销**。因此：

- 发版前若有新的 `V*.sql`，务必先备份数据库：

  ```bash
  docker exec at-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction anttransfer' \
    | gzip > /home/ubuntu/backup-$(date +%F-%H%M).sql.gz
  ```

- 备份范围也必须覆盖文件卷，否则用户上传的内容无副本：

  ```bash
  docker run --rm -v anttransfer_files-data:/src -v /home/ubuntu:/out alpine \
    tar -czf /out/files-$(date +%F).tar.gz -C /src .
  ```

- 若新迁移包含**删列 / 改类型**这类不可逆操作，只能「回滚代码 + 从备份恢复数据库」，
  没有别的捷径。

确认新版本稳定运行几天后，再删除留底：

```bash
rm -rf /home/ubuntu/anttransfer.bak /home/ubuntu/anttransfer.failed
```

## 七、首次部署（仅在重建服务器时使用）

日常发版**不要**走这里。完整流程：

```bash
# 1) 基础依赖
apt-get update && apt-get install -y docker.io docker-compose-v2 nginx git
systemctl enable --now docker nginx

# 2) 部署目录（名字必须叫 anttransfer）
mkdir -p /home/ubuntu/anttransfer
tar -xzf /tmp/anttransfer-src.tar.gz -C /home/ubuntu/anttransfer
cd /home/ubuntu/anttransfer

# 3) 生成 .env —— 两项必填，缺失时 compose 会直接报错退出
cp .env.example .env
SECRET=$(openssl rand -base64 48)
sed -i "s|^DB_PASSWORD=.*|DB_PASSWORD=<设一个强密码>|"            .env
sed -i "s|^AUTH_ACCESS_TOKEN_SECRET=.*|AUTH_ACCESS_TOKEN_SECRET=${SECRET}|" .env
sed -i "s|^ANTTRANSFER_CORS_ALLOWED_ORIGINS=.*|ANTTRANSFER_CORS_ALLOWED_ORIGINS=http://101.43.55.53|" .env
chmod 600 .env
cat .env                            # 核对一遍
```

> ⚠️ `.env` 承载数据库密码与 JWT 签名密钥，**不在版本控制里、全服仅此一份**。
> `DB_PASSWORD` 丢了打不开已有数据，`AUTH_ACCESS_TOKEN_SECRET` 变了所有人立刻掉线。
> 生成后请立刻离线另存一份。

```bash
# 4) 起服务（首次会完整构建镜像，最慢的一次）
docker compose up -d --build
docker compose ps

# 5) Nginx 站点
cp deploy/nginx/anttransfer.conf /etc/nginx/sites-available/anttransfer
#    按服务器实际情况改 server_name 与 root（root 应为 /var/www/anttransfer）
ln -sf /etc/nginx/sites-available/anttransfer /etc/nginx/sites-enabled/anttransfer
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

前端产物按第四章上传到 `/var/www/anttransfer` 后，访问 `http://101.43.55.53/` 即可。

## 八、常见故障速查

| 现象 | 原因与处置 |
| --- | --- |
| `docker compose up` 报 `必须设置数据库密码 DB_PASSWORD` / 密钥相关错误 | 新目录里缺 `.env`。从 `.bak` 拷回来：`cp ../anttransfer.bak/.env .` |
| 构建卡在 `transferring context` 很久 | 前端 `node_modules` 混进了构建上下文。确认 `.dockerignore` 里的 `web/node_modules/` 还在 |
| 启动日志报 `Access denied for user` | `.env` 的 `DB_PASSWORD` 与 MySQL 卷里实际密码不一致（多为换了 `.env`）。用原密码；确实丢了只能重置库内密码 |
| 重启后用户文件 / 断点续传全没了 | 卷没挂上或 project 名变了。`docker volume ls` 看是否存在 `anttransfer_files-data`；确认目录名没改 |
| 页面白屏 | 前端 `dist` 没传或空目录；也可能是 `index.html` 被缓存（Nginx 里该文件应配为不缓存） |
| 上传大文件在 Nginx 层被拒 | `client_max_body_size` 需 ≥ 100m（后端上限 80MB） |
| 实时通知一直「正在建立连接」 | Nginx 缺 `/api/ws/` 的 WebSocket Upgrade 转发块，对照 `deploy/nginx/anttransfer.conf` 补齐 |
| 接口全量 404 | `proxy_pass` 结尾多写了 `/`，前缀被剥掉。必须写 `proxy_pass http://anttransfer_backend;` |

## 九、红线

1. 🚫 任何时候都不要执行 `docker compose down -v`、`docker volume rm`。
2. 🚫 不要修改部署目录名，不要删 `.env`。
3. 🚫 不要把 `mysql:3307`、`redis:6379`、`server:8080` 的三个 `127.0.0.1` 绑定改回
   `0.0.0.0`——那等于把数据库和 Redis 直接挂到公网上。
4. 🚫 不要把 `.env`、私钥提交进仓库。
5. ✅ 发版前先 `git status` 确认干净、记下 commit id；发版后跑完第五章的验证清单。
