## 0. 通用前置

| 角色 | 说明 |
| --- | --- |
| 匿名 | 无 token |
| 用户 A / B | 同角色（普通用户），各自持有 `fileA` / `fileB`、`taskA` / `taskB` 等私有资源 |
| 审计员 | 仅具备审计读取权限（`PERM_AUDIT_LOG_READ`） |
| 管理员 | 全权限 |

**判定基线**：越权成功的唯一标准是**拿到了不属于自己的数据或执行了越权动作**；
返回 403 但**顺带泄露了资源是否存在**（404 vs 403 可区分）也算信息泄露，需记录为低危。

**覆盖率口径**：✅ 仅代表「有可执行断言载体且已实跑通过」，**不代表已做渗透验证**；
载体为单元测试时（Mock 掉 DB / Redis），证明的是「代码路径上的判定与副作用」，不是「真库真缓存下也不会越权」——
这类差距在 §5「遗留」里逐条写明，不得用 ✅ 反推「该场景已端到端验证」。

**前端红线（来自错误码契约）**：`1003`（无权限，403，策略 D）应**就地提示、禁止引导登录**；
只有 `1006`（Token 无效，401，策略 C）才跳登录页。断言中必须区分，避免把 403 当未登录处理。

## 4. 断言写法要求（避免「假通过」）

1. **不能只断言状态码**：越权删除必须再断言「目标资源仍然存在」；越权写必须断言「未落库」。
2. **必须断言响应体**：403 的响应体不得夹带被保护资源的字段（防止「拦了动作但漏了数据」）。
3. **必须区分 401 / 403**：`1001/1002/1006` 是认证问题（可引导登录），`1003` 是授权问题（禁止引导登录）。
4. **副作用断言优先**：越权测试的价值在于「数据没变」，而不在于「返回了 403」。
5. **对遍历类用例设阈值**：连续 IDOR 遍历应触发告警（当前依赖日志，需配合监控）。
6. **载体要能「反向失败」**：每个拒绝用例都应配一条「本人 / 合法参数下必须放行」的对照断言，
   否则「一律拒绝」的实现也能让用例全绿（各新增类均已内置此类对照）。
